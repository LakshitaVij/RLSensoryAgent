## How effects are applied (Lakshita, applies to every action and signal)
**Effects move a signal toward the subject's own baseline and never past it.** If a signal is already at baseline, the action changes nothing. Raw-unit effects from papers (e.g. S07: heart rate −1.7 bpm, breathing −1.2/min, RMSSD +2.1 ms) are therefore **caps on how far toward baseline the signal can be moved**, not shifts applied unconditionally. Effects were measured in calm people at rest in several papers (S07, You et al. 2021), which is another reason not to apply them past baseline.

## **Version 1 duration rule (Lakshita, supersedes everything under "Duration levels" below): ONE standard duration per action, no short/mid/long levels.** Reason: with several levels the agent would probably always pick the longest (effect grows with minutes and nothing penalizes time), which would "mess up" Version 1. The v1 menu is therefore A1 do nothing + A2, A3, A5, A7, A9, A10, A11 = 8 actions before the later blank-cell decision (see below). The proportional short-effect rule and the 2-level/3-level tables below are **retired for v1** (kept only as history). **Single duration (Lakshita): 5 minutes for every action** (A2, A3, A5, A7, A9, A10, A11). Direct dose matches: A2 (You 2021, 5-min session), A7 (S15, 5-min task), A10 (Balban, 5 min). **Extrapolated to 5 min and labeled so in the README:** A5 (S14, 20 min), A9 (S20, 20 min), A3 (S06 4 min recovery; S07 10 min). A11 humming has no usable dose or effect (blank). With one duration and a 2-min decision step, a running action (5 min) locks out about 2 decisions; the cap stays 4 actions/hour.

## Environment (Step B) design decisions (Lakshita, interviewed one at a time; started 2026-10-22)
1. **Episode:** one subject's whole recording after the 20-min baseline (start at minute 20, run to the end of the recording); each training episode picks one of the train subjects. About 67–97 min, i.e. about 33–48 decisions at one per 2 min (Claude's arithmetic from the 87–117 window counts). Random-start segments can be tried later if the agent overfits.

2. **Effect timing:** full cited effect during the 5-min block; after the block, the paper's 'after' value where it has one (e.g. paced breathing HRV about +26 ms during vs about +4 ms after), otherwise a linear fade to zero over the 5 min after (the fade is a labeled design choice).
3. **Carry-forward:** a temporary nudge on top of the real recording. The agent sees the real signal plus the action's effect toward baseline; when the effect fades the values return to exactly what the real recording shows. The recording is never changed. Limitation (for the README): an action cannot change later body behaviour (lasting calm is not modelled); that is the 'natural dynamics v2' idea.
4. **Converting effects into environment units:** effects in plain units (HRV ms, heart rate bpm, breathing /min) are added to the real raw value, capped so they never pass the subject's baseline mean, then the baseline-spread value is recomputed (z = (value − baseline mean) / baseline spread, then capped at ±5). Haptic pulse (g = 0.54) is already in baseline spreads (× the subject's baseline spread, labeled assumption). Meditation = extra ≈ 23% pull of the stress-induced sweat rise toward baseline (labeled estimate). Calming audio sweat = EDA excess above baseline decays about 17% faster (101.3 / 121.3, S06). **PMR sweat (Lakshita): about 1.0 baseline spreads, from S14's η² = 0.51 via Cohen's f = sqrt(η²/(1 − η²)) = 1.02 — a labeled ROUGH conversion** (η² describes within-group change over a 20-min session, applied here to a 5-min effect); sensitivity-test smaller values (e.g. 0.5) later.
5. **Timing grid:** decisions every 2 min; an action's effect runs 5 min, and the agent regains control at the next step after it ends (minute 6), so an action effectively occupies 3 decision steps (a 5-min effect, a 6-min lockout).
6. **Lockout style:** action masking (cite Huang & Ontañón 2020, arXiv 2006.14171). During the lockout (minutes 0–6 after an action starts) only "do nothing" is allowed; every other action gets probability zero. Rewards still count every 2-min step.
7. **Cap counting:** rolling 60 minutes — an action can start only if fewer than 4 actions began in the previous 60 min (30 decision steps); at the cap, the same masking applies (only "do nothing"). "Do nothing" never counts toward the cap. Cap value 4 stays a labeled design choice.
8. **Observation at each 2-min decision:** the 16 capped (±5) baseline-normalised features of the latest completed 60 s window + 3 bookkeeping numbers (minutes left in the current lockout, actions started in the last 60 min, cap reached yes/no). The bookkeeping is not sensor data or labels (rule 9 safe). 19 numbers.
9. **Reward per 2-min step = gain versus do-nothing:** reward = Σ over the four signals of weight × (|z| with no action − |z| with the action), using the replay's real values as the do-nothing counterfactual (weights HRV 35, heart rate 25, sweat 20, breathing 20; |z| = distance from baseline in baseline spreads, capped at ±5). "Do nothing" always scores exactly 0; an action scores 0 when the person is already at baseline (effects never pass baseline). **Consequence for the README:** because effects come from the spec, the agent can only learn the spec's effects, so Version 1 tests whether PPO recovers the spec's best actions, not whether those actions work in reality.
10. **Train/validation split inside the 9 usable train subjects:** fixed 7 train / 2 validation, picked once and frozen in `val_split.json` (`src/make_val_split.py`, numpy default_rng(42), integer-sorted ids, numpy 2.5.3): **train S5, S6, S7, S9, S13, S15, S16; validation S4, S14.** Held-out 5 (S2, S8, S10, S11, S17) untouched. Leave-one-subject-out can be used later for final Version 1 numbers.
11. **Version 1 "correct action" scoring (starting sketch, Lakshita may change it):** on the 2 validation subjects — (a) mean reward per episode (do-nothing = 0, so > 0 means it beats do-nothing); (b) match rate: share of decisions where the agent picks the action with the highest immediate environment gain among the currently available actions (greedy oracle); (c) the mix of chosen actions (to catch an agent that always picks one action). Whether the chosen action also matches the paper-supported action for the state is read from (b), since the environment's gains come from the cited effects. **DECIDED (Lakshita, 2026-10-23):** the two scores are mean reward per episode (beats do-nothing?) and fraction of the best possible score; the action mix is shown beside them; the match rate against the hindsight oracle is reported but is not the headline, because the oracle sees the future. Evaluated across the 9 usable subjects with leave-one-subject-out on development data, and once on the 5 held-out subjects at the end.

**Files the environment reads (per usable subject SX):** `data/features/SX_features.csv` (`raw_*`, `z_*`, `zc_*` per 60 s window), `data/features/SX_baseline.csv` (baseline mean and spread, ddof = 1, of each raw feature over the first 20 windows; z = (raw − baseline_mean) / baseline_sd), `val_split.json` (train/validation ids). Window labels are in `data/eval_only/` and must not be read by the environment.

**Env build decisions (Lakshita, 2026-10-22, while Claude builds the environment) — these supersede items 5 and 6 above where they conflict:**
- **Step reward** = the average (not sum) of the gains over the step's two 60 s windows.
- **Never away:** effects act only on the stressed side of baseline (toward baseline, never past it, never away from it). Gains are therefore always ≥ 0, and do-nothing is exactly 0.
- **Missing values:** a signal with a missing value in a window gets zero gain for that window (no filling); the step info reports how many were skipped.
- **Lockout = 10 minutes** (5-min block + 5-min after window), so effects never overlap and no overlap rule is needed. The agent regains control at minute 10 (5 decision steps), which divides evenly on the 2-min grid. This replaces the earlier 6-minute lockout. "Minutes left in lockout" runs 10 → 0. The cap of 4 per rolling 60 min stays (at most 6 actions per hour are possible anyway).

**Env build decisions, continued (Lakshita, 2026-10-22):**

The wrist/chest mirroring is a labeled design choice. HRV and breathing rate have no twin.
- **End of recording:** `truncated=True` (not terminated); the PPO should bootstrap the last state's value.
- **Forbidden action:** the environment raises an error if the PPO picks a masked action.

## Step A feature definitions (Lakshita, 2026-10-08; each cited to the WESAD paper, Schmidt et al. 2018, Table 1 / Sec. 4.1, unless marked)
- **Window:** 60 s for body signals, 5 s for movement; windows are non-overlapping 60 s windows (the paper's 0.25 s shift is for classification and is not used) [design choice].
- **Trend:** slope within the 60 s window (WESAD slope features ∂EDA and ∂TEMP), expressed in baseline spreads. **Decided (Lakshita):** the paper computes slopes only for EDA and TEMP; for EMG and breathing the raw signal oscillates around zero, so their trend = slope of a derived quantity: EMG trend = slope of the EMG activity level (mean absolute value per 5 s) within the window; breathing trend = slope of the breathing rate within the window. These two are **our own labeled design choice**, beyond the paper's precedent.
- **Movement level:** standard deviation of the 3D acceleration magnitude over a 5 s window (WESAD σ_ACC,3D), averaged over the 12 five-second windows inside each 60 s window; wrist ACC converted from 1/64 g to g.
- **Muscle activity level:** absolute integral of the EMG over the window divided by window length (WESAD ‖EMG‖).
- **Breathing depth:** range (max − min) of the cleaned breathing signal within the window (WESAD range_RESP).
- **Wrist heart rate:** pulse peaks by Elgendi et al. (2013) via NeuroKit2 (`ppg_peaks`, method "elgendi", `correct_artifacts=True` = Lipponen & Tarvainen 2019), sampling rate set to the true 64 Hz; HR = 60 / mean NN interval. **Wrist HRV is DROPPED from the state (Lakshita):** on S4, wrist RMSSD stayed implausible even after the cited artifact correction (46–437 ms, mean 284 ms), because 64 Hz pulse timing is too coarse; chest RMSSD (78–160 ms) is used. **State = 16 features.**
- **Chest heartbeats:** Pan & Tompkins (1985) via NeuroKit2 with `correct_artifacts=True` (Lipponen & Tarvainen 2019). Heart rate = 60 / mean NN interval; RMSSD from successive NN differences inside a window; NN intervals are assigned to the window containing their second beat.
- **HRV window:** 60 s as in WESAD, with a stated caveat in the README that HRV from 60 s is noisier than the commonly cited 5-minute short-term norm (not verified this session).
- **Cap on extreme values (Lakshita):** baseline-normalised values are capped at ±5 baseline spreads (columns `zc_*`; uncapped `z_*` kept for transparency). **5 is a labeled design choice, not from a paper; test 3 and 10 later.** Reason: some subjects' sweat levels barely varied in the baseline, giving |z| up to 454 (S16 chest EDA level), 192 (S13), 286 (S16 wrist EDA level).
- **Baseline normalisation:** for each feature, mean and spread are taken from the subject's first 20 min of windows (20 non-overlapping 60 s windows), never from labels; features are expressed as (value − baseline mean) / baseline spread [design choice].
